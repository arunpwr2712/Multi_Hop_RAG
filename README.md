# Multi-hop Causal RAG Full Stack

This repository contains a full-stack implementation of a multi-hop causal retrieval-augmented generation (RAG) system.

- `backend/` — FastAPI backend wrapping the core `multi_hop_causal_rag` library (retrieval, causal graph, pipeline, evaluation).
- `frontend/` — Next.js UI for chat, chain inspection and graph visualization.

This README explains what the project contains, how to set it up locally, how to run the backend, frontend and CLI, and where to find evaluation tools and generated artifacts.

## Requirements

- Python 3.10+ (3.12 tested)
- Node.js 16+ / npm (for frontend)
- System packages for `faiss-cpu` (installed via pip on supported platforms)

## Quick setup — Backend

1. Create and activate a Python virtual environment inside `backend/`:

```bash
cd backend
python -m venv .venv
.\.venv\Scripts\activate    # Windows PowerShell
source .venv/bin/activate   # macOS / Linux
```

2. Install Python dependencies:

```bash
pip install -r requirements.txt
```

3. Ensure FAISS index files exist in `backend/faiss_index_512/` (`index.faiss` and `index.pkl`). If they are missing, build them:

```bash
python -m multi_hop_causal_rag.build_faiss_index
```

4. Start the API server:

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

The backend serves these primary endpoints:

- `GET /api/health` — readiness/health check
- `POST /api/chat` — chat query (RAG)
- `GET /api/graph` — causal graph data
- `GET /api/last-result` — latest assistant result
- `POST /api/reset` — reset runtime graph/state

## Quick setup — Frontend

1. From repository root:

```bash
cd frontend
npm install
npm run dev
```

2. The dev UI will be available at `http://localhost:3000` by default. If the frontend cannot reach the backend, set:

```bash
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

## Interactive CLI (local chat)

If you prefer a terminal chat UI (local, useful for debugging), run the CLI packaged with the core library:

```bash
cd backend
python -m multi_hop_causal_rag.main
```

Notes:
- The CLI expects the FAISS index in `backend/faiss_index_512/`. If the index files are missing the CLI will raise an error.
- The CLI can generate graph visualization files under `backend/multi_hop_causal_rag/graph_outputs/` and will attempt to open an interactive HTML graph if pyvis is installed.

## Evaluation & Ablation Experiments

- Benchmark runner (backend): `backend/multi_hop_causal_rag/evaluation/run_backend_benchmark.py`
- Ablation experiments: `ablation_study_experiments/run_experiments.py`

Example (quick smoke test of backend benchmark):

```bash
cd backend
.\.venv\Scripts\activate
python backend/multi_hop_causal_rag/evaluation/run_backend_benchmark.py --max-cases 1 --top-k 3
```

Generated experiment outputs (tables, charts) are written under `ablation_study_experiments/results/` and can be regenerated by re-running the experiment scripts.

## Configuration

- Core runtime/config lives in `backend/multi_hop_causal_rag/config.py`. Edit values there or override behavior via environment variables as documented in that file.
- LLM connectivity (Ollama or other) is configured in the same config module — set `llm.base_url` and `llm.model` when using Ollama.

## Generated artifacts and safe cleanup

These files/folders are generated and can be deleted safely; they will be recreated as needed:

- `frontend/node_modules/` — reinstall with `npm install`
- `frontend/.next/` — Next.js build cache
- `**/__pycache__` and `*.pyc` — Python bytecode caches
- `ablation_study_experiments/results/*` — evaluation outputs (charts, CSV, metrics)
- `backend/multi_hop_causal_rag/graph_outputs/*` — exported graph images/HTML (but `causal_graph_state.json` is runtime state used by the backend and is preserved)

To clean regenerated files (example):

```powershell
Remove-Item -Recurse -Force frontend\.next, frontend\node_modules
Get-ChildItem -Recurse -Filter "__pycache__" | Remove-Item -Recurse -Force
```

## Troubleshooting

- Missing FAISS index error: run `python -m multi_hop_causal_rag.build_faiss_index` from `backend/` to build indexes.
- Ollama timeouts / LLM errors: check `backend/multi_hop_causal_rag/llm_interface.py` and the `llm` config in `config.py` for timeout and fallback settings.
- If the frontend cannot reach the backend make sure both dev servers are running and `NEXT_PUBLIC_API_BASE_URL` points to the backend base URL.

## Notes for contributors

- Keep model and data files out of version control. Large indexes and datasets belong in `backend/faiss_index_512/` and dataset folders.
- Use the included benchmark and ablation scripts to reproduce reported metrics. See `ablation_study_experiments/` for experiment configs.
